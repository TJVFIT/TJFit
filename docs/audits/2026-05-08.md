## 1. Executive Summary

1. **Wrong domain in 11 places.** Code defaults and hardcoded fallbacks point to `tjfit.com`, but production is `tjfit.org` per `project_domain.md`. This includes the Organization schema for Google, PDF footer, every legal-page support email (`support@tjfit.com` × 5 locales), and both root layouts. If `NEXT_PUBLIC_SITE_URL` is unset on Vercel, search engines and PDFs will brand the wrong domain.
2. **In-memory rate limiter (`src/lib/rate-limit.ts`) is a no-op on Vercel.** Each serverless invocation gets its own `Map`, so the limit is effectively per-request. Anything depending on it for abuse protection (TJAI chat, contact forms) is unprotected.
3. **`coming-soon-launch-page.tsx` ships untranslated Turkish.** Lines 43–66 use `Canli`, `don`, `cok yakinda` — Latin-only stand-ins for Türkçe diacritics. Same file, all 5 locales served from one hardcoded record. Looks unfinished to a Turkish customer.
4. **Sale handler will overwrite the buyer's role to `user`** if they're already a coach/admin who happens to buy via Gumroad. `src/app/api/webhooks/gumroad/handlers/sale.ts:78-83` upserts `{ role: "user" }` with `ignoreDuplicates: true` — the comment claims it's additive, but if Postgres returns no row on conflict the upsert is a no-op, so this is actually safe. Verify on Postgres ≥14 (low risk, but worth confirming with `select` after).
5. **Gumroad webhook — no replay window check.** Unlike Paddle (`paddle-webhook-verify.ts:31` enforces 5-min `MAX_AGE_SEC`), Gumroad verify (`gumroad-webhook-verify.ts`) only checks HMAC. A leaked-once signed body could be replayed forever. Idempotency saves the credit grant from double-firing, but anyone holding a captured body can trigger arbitrary state churn.
6. **`coach_payouts` and `sale_commissions` exist, but there is no payout pipeline yet.** The Gumroad sale handler logs commission rows; nothing aggregates them into payouts. Owner needs to know v5 is "foundation" — money tracking works, paying coaches doesn't.
7. **TJAI generate refund path is incomplete on uncaught throws.** `src/app/api/tjai/generate/route.ts:155-165` admits this in a comment. If `runPlanGenerationPipeline` throws (vs returns `{ok:false}`), the user is charged a credit and gets nothing. Loss is small (1 credit) but real and trust-eroding.
8. **53 Supabase migrations, no rollback playbook in tree** beyond `docs/engineering/major-changes-and-rollback.md`. `scripts/PASTE_IN_SUPABASE_SQL_EDITOR.sql` exists. Several migrations re-`drop policy if exists ... ; create policy ...`, which is OK, but there is no migration version table check; running the wrong order will fail loudly but require manual intervention.
9. **Branch sprawl.** ~30 unmerged branches across `auto/codex/*`, `auto/cursor/*`, `claude/*`, `cursor/*`, `codex/*`. None obviously stale-and-deletable without owner sign-off; many appear to be agent-staging branches that should be cleaned up after merge.
10. **Pricing directive honored.** All 95 program/diet `price` fields in `src/lib/content.ts` are `0` (lines 144–943, contiguous). No invented prices. The `formatMoney` helper in `immersive-home.tsx:54-60` still does `n * 0.029` (TRY → EUR conversion at a hardcoded rate) — fine while prices are 0, but will display the wrong currency math the moment Joseph sets a non-zero price.

## 4. Critical Issues (must fix before broad customer launch)

### C1. Wrong canonical domain everywhere code falls back
`src/app/layout.tsx:35` — `siteUrl = "https://tjfit.com"` (root metadata fallback)
`src/app/[locale]/layout.tsx:24` — `const SITE_URL = process.env.NEXT_PUBLIC_SITE_URL ?? "https://tjfit.com"` (locale layout, used for `alternates.languages`)
`src/components/brand-organization-json-ld.tsx:10` — `return "https://tjfit.com"` (Organization JSON-LD fallback)
`src/components/intro-animation.tsx:287` — `Est · tjfit.com` (visible UI string in intro)
`src/lib/tjai-pdf-builder.ts:440` — `pdf.text("tjfit.com", ...)` (paid PDF footer)
`src/lib/legal-hub-copy.ts:81,139,161,169,177,185,193` — `support@tjfit.com` in 5 locales (legal page email)

**Fix:** sweep replace `tjfit.com` → `tjfit.org`. The code already prefers `NEXT_PUBLIC_SITE_URL` when set, so production probably renders the right URL today; but PDFs, the visible intro string, the JSON-LD fallback, and **all 5 legal-page support emails** are static and will leak the wrong domain regardless of env. Priority: high — paying customers see the PDF and legal page.

### C2. `vercel.json` and route disagree on TJAI generate timeout
`vercel.json:4` — `"maxDuration": 60`
`src/app/api/tjai/generate/route.ts:13` — `export const maxDuration = 90`

Vercel honors the lower of the two for the function execution wall (Vercel will cap at 60s on Hobby/Pro per region). Long plan generations beyond 60s get killed and the credit refund only fires inside the inner `if (!result.ok)` branch — uncaught timeout = credit lost.

**Fix:** raise `vercel.json` to 90, or lower the route export to 60 to match — pick one source of truth. Then make the route's `try/finally` refund credits on any throw (not just `result.ok === false`), as the in-code comment at line 158-163 already acknowledges.

### C3. In-memory rate limiter is non-functional under serverless
`src/lib/rate-limit.ts` — module-level `Map` survives only within a single warm Lambda. Vercel can spawn N concurrent invocations; an attacker hitting `/api/support/contact`, `/api/tjai/chat`, or auth endpoints in parallel routes around it.

Search for usages confirms it's wired in at least a few places (chat, support contact). **Fix:** swap for an Upstash-Redis or Supabase-backed limiter (the schema already has `tjai_ai_call_logs` you could repurpose, or add a simple `rate_limit_buckets` table with `(key, window_start)`).

### C4. Gumroad webhook missing replay-window check
`src/lib/gumroad-webhook-verify.ts:15-30` — verifies HMAC but does not enforce a timestamp or `MAX_AGE_SEC`. Compare to `src/lib/paddle-webhook-verify.ts:31` which enforces `MAX_AGE_SEC = 300`.

Idempotency (insert into `payment_webhooks` keyed by event_id) prevents double-grant of credits, but a captured signed body could still be replayed for as long as the secret is unchanged. **Fix:** if Gumroad provides a timestamp header (`X-Gumroad-Timestamp` or similar — verify with Gumroad docs), add a 5-min window. If they don't, log a note and document the residual risk.

### C5. Client-trusted role escalation attempt is blocked, but worth re-verifying
`src/app/api/admin/authorize-coach/route.ts:50-58` — uses `requireAdmin()` which mixes ADMIN_EMAILS + DB role check; promotes any `user` profile to `coach` purely on email match. Email here is the **target** (the coach being authorized), not the requester. This is correct. Just flag that any compromise of an admin login = arbitrary coach role grants. Keep MFA on admin emails.

### C6. RLS audit doc is real but stale
`supabase/RLS_AUDIT.md` exists and lists tables/policies, but stops covering migrations after the early `20260331*` files. The v5 schema (`product_gumroad_sync`, `tjai_credit_packs`, `sale_commissions`, `coach_payouts`, etc.) is RLS-enabled in the migration (`20260503100000_v5_payment_automation.sql:58-59,126-127,352-374`), but it is not documented in the audit.

**Fix:** regenerate the audit doc against current migrations before any external compliance review.

### High

**H1. `formatMoney` hardcodes a TRY→EUR rate.**
`src/components/immersive-home.tsx:54-60`:
```ts

```
Not a bug today (all prices = 0), but the moment Joseph sets a price it'll display the wrong currency math. **Fix:** centralize rates in `src/lib/pricing/` (which already exists per `src/lib/pricing/locale-tier.ts`) and read from there, or just emit local currency without a multiplication.

**H2. Gumroad sale handler uses `listUsers()` as fallback — O(N) and paginated.**
`src/app/api/webhooks/gumroad/handlers/sale.ts:102-104`:
```ts
const { data: list } = await admin.auth.admin.listUsers();
const match = list?.users?.find((u) => u.email?.toLowerCase() === email.toLowerCase());
```
`listUsers()` returns 50 users by default and requires pagination. With more than 50 users in `auth.users`, this fallback silently misses the buyer and creates a duplicate. **Fix:** use `admin.auth.admin.listUsers({ filter: ... })` or query `auth.users` via SQL by email.

**H3. Magic-link generated but never delivered.**
`src/app/api/webhooks/gumroad/handlers/sale.ts:86-92` — calls `auth.admin.generateLink({ type: "magiclink", email })` but throws away the returned link without sending it. New buyers get a confirmed account but no way to log in. The comment claims the Resend handoff "lives in a separate template" — search confirms no email is sent. **Fix:** wire to `sendWelcomeEmail` with the magic-link URL.

**H4. Webhook fire-and-forget `void admin.from(...)` calls.**
`src/app/api/tjai/chat/route.ts:105` writes a `tjai_ai_call_logs` insert as `void`. If it fails, you lose the audit log and can't observe the failure. Acceptable for high-volume telemetry; flagged for awareness.

**H5. TJAI generate refund is fragile.**
`src/app/api/tjai/generate/route.ts:155-165` — uncaught throws don't refund. The comment owns this. **Fix:** lift `creditConsumed`/`creditsRemaining` outside the try block, refund in a `finally` if `result` is falsy.

**H6. Two Supabase client patterns coexist (`@/lib/supabase/server` and `@/lib/supabase-server`).**

`consume_tjai_credit` (migration `20260503100000_v5_payment_automation.sql:171`) uses `select ... for update`. Correct for safety, but on a hot-path generate this serializes all credit consumes against the same profile row — which is fine because it's per-user (a single user can't generate two plans truly concurrently anyway). No fix needed; flagged so future load testing accounts for it.
