# Mobile + RTL Audit — 2026-05-27 (Plan2 phase 16)

Static review of homepage (`luxury-home.tsx` / `immersive-home.tsx`), bundles list+detail, checkout, TJAI quiz. No live device probe — heuristic from class usage.

## Tap targets
- Primary CTAs use `h-11` (44px) — meets the practical mobile minimum (WCAG 2.2 target-size + Apple HIG). ✓
- Verify smaller chip/filter buttons (leaderboard tabs, quiz options) hit ≥44px on mobile in a future device pass.

## Horizontal scroll
- `site-shell` wraps content in `overflow-x-hidden` — global guard against horizontal scroll. ✓

## RTL (Arabic) — issues found
| Issue | Where | Severity |
|---|---|---|
| `tracking-tight` on headings | `luxury-home.tsx`, `bundles/page.tsx` | P3 — negative letter-spacing on Arabic text degrades legibility. Should be gated `ltr:tracking-tight` or removed for `ar`. |
| `pl-*` / `pr-*` physical padding | 2 occurrences in `luxury-home.tsx` | P3 — should be logical `ps-*` / `pe-*` so they flip in RTL. Low count, low impact. |
| `dir`/RTL handling | present in `site-top-bar.tsx` + `[locale]/layout.tsx` | ✓ direction is set at the layout level |

## Verdict
No P0/P1 mobile blockers found statically. Global `overflow-x-hidden` + 44px primary CTAs are healthy. The RTL items are P3 polish: `tracking-tight` on Arabic headings + a couple of physical-padding classes. Recommend a real device/browser pass (BrowserStack or `/verify` with a running dev server) to confirm no clipping/overlap on 360px width and to eyeball Arabic layout — static analysis can't see rendered overflow.

## Recommended follow-ups (P3)
- Replace `tracking-tight` with `ltr:tracking-tight` (or drop for Arabic) on headings.
- Swap the 2 `pl-`/`pr-` for `ps-`/`pe-` in `luxury-home.tsx`.
- Device pass at 360/390/768px widths across the 4 audited surfaces.
