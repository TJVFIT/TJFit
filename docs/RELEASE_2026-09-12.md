# TJFit release verification — 12 September 2026

This is an implementation and activation checklist, not evidence that all services are live. Preserve customer records and keep an unverified purchase path closed. Supplier quotations, acquisition costs, identity documents and payment credentials belong outside this repository.

## Authority and rollout order

Shopify owns physical products, guest checkout, orders, payment state and fulfillment. Supabase owns accounts, digital entitlements, intake, saved plans and progress. An equipment enquiry is not an order. A browser payment return never grants digital access.

1. Build and preview this exact revision, with all purchase and AI gates closed.
2. Restore production Supabase service availability. Do not replace the existing authentication/database project. Apply additive commerce and TJAI migrations in filename order at the coordinated release; the saved-plan write restriction requires the new server routes and must not be rolled out independently against the old client-write route.
3. Verify an isolated Netlify preview, both background functions, authentication, redirects and signed test webhooks. Use synthetic test customers; test receipts must not become live access.
4. Enable inference only after the dedicated Groq key, inference Zero Data Retention, deployed worker and real quality/recovery checks pass. No paid fallback is configured.
5. Publish the verified public experience. Change root/www DNS only after preview, callbacks and TLS pass. Preserve the existing `shop.tjfit.org` CNAME to `shops.myshopify.com` and retain the prior root/www records for rollback.
6. Enable digital checkout only after Lemon account/product/payout approval and end-to-end verification. Enable equipment checkout only for an authorized merchant, verified supplier and approved economics. These are independent activation decisions.

The profile-write-permissions migration is independently compatible with the existing signup trigger. It has been applied in production and verified by privilege metadata: authenticated users cannot change role, credits, tier, verification or XP. The approved profile presentation fields remain writable. Existing role/credit values were not reset, and their historical provenance has not been audited.

## Hosting and environment

Use Netlify Free with automatic paid upgrades off. The current Vercel team is Hobby; no commercial production deployment to that plan is part of this release. The repository contains `netlify.toml`, a background generation function and a five-minute recovery function. Local packaging is not a deployed-function test.

`vercel.json` disables automatic Git deployments for this revision, so pushing the reviewed branch does not publish it to the existing Hobby project. This does not remove the currently served deployment or change DNS. See [Vercel Git configuration](https://vercel.com/docs/project-configuration/git-configuration#turning-off-all-automatic-deployments). CI uses Node 22 to match the intended Netlify runtime.

Set `NEXT_PUBLIC_SITE_URL` separately for each environment. A preview uses its own HTTPS origin, production uses `https://tjfit.org`, and local development uses its actual localhost port. Never copy a production checkout return origin into a preview. Add the exact preview and production callback paths in Supabase's allowed redirect configuration, preserving existing valid callbacks. Do not use a broad wildcard for arbitrary domains.

Transfer only required, reviewed settings through the hosting secret store: existing Supabase URL/anonymous key/service-role key, the correct historical verification settings, scoped Lemon test or live configuration, the dedicated Groq inference key, and the random worker secret. Keep provider keys, service-role keys and webhook secrets server-only. Do not transfer expired Vercel OIDC credentials or unrelated paid-provider keys.

The new gates default closed. Deploy previews disable live Lemon checkout and the worker in `netlify.toml`; enable a preview worker only as a deliberate isolated verification step. Production rejects Lemon test checkout even when other configuration is present. Existing saved data remains readable when a new provider is unavailable, subject to database availability.

## Known content limits

Bundle downloads include the verified files and use Unicode fonts, but the deeper exercise instructions and recipes in the existing bundle library remain English. The checkout now discloses this in all five UI languages. Generated nutrition uses estimated catalog values; it is not brand-label or clinical nutrition. No production model-quality claim is made without real Groq test evidence.

The hardcoded-copy scanner reports remaining legacy UI text instead of hiding it behind a broad exemption. Locale-key parity and core-flow translation checks must be reported separately from that wider backlog. CSP remains report-only; a passing dependency or bundle scan is not a claim that every security risk is eliminated.
